# Case API (v1)

The interactive OpenAPI docs are at `/api/docs/` (Swagger UI) and the raw schema is at `/api/schema/`. Both are generated by drf-spectacular from the code, so they are always current.

## Conventions (shared contract)

- **Base path:** `/api/v1/`
- **Authentication:** send `Authorization: Token <key>` (DRF token auth). Browser sessions also work, with CSRF checks enforced. Every endpoint requires authentication.
- **Pagination:** `?page=&page_size=` (default 20, maximum 100). Responses look like `{"count", "next", "previous", "results"}`.
- **Errors:** always `{"error": {"code", "message", "details"}}`.
  - `details` maps each field to a list of messages when validation fails.

| HTTP | `code` | When |
|---|---|---|
| 400 | `validation_error`, `unsupported_file_type`, `file_too_large`, `file_content_mismatch`, `too_many_attachments`, `already_linked`, `empty_file` | Bad input |
| 401 | `not_authenticated`, `authentication_failed` | No token or an invalid one |
| 403 | `permission_denied` | You can see the case but aren't allowed to take that action |
| 404 | `not_found` | The case doesn't exist **or isn't visible to you** (this avoids revealing whether other users' cases exist) |
| 405 | `method_not_allowed` | |
| 409 | `invalid_transition` | Not allowed from the case's current status |
| 429 | `rate_limited` | Throttled (see `Retry-After`) |

## Visibility

| Role | Sees |
|---|---|
| Student / lecturer | Cases they submitted |
| Authority officer | Cases currently assigned to their authority, plus their own submissions |
| Case admin / system admin | All cases |
| Management | All cases, read-only |

Internal notes, assignment notes, deadline history and escalations are visible only to staff (admins, management and the assigned authority). Submitters see role labels instead of staff names.

## Endpoints

| Method | Path | Who | Purpose |
|---|---|---|---|
| GET | `/cases/` | any | List visible cases. Filters: `status` (comma-separated), `case_type`, `priority`, `category`, `assigned_authority`, `mine=true`, `active=true`, `overdue=true`, `search`, `ordering` |
| POST | `/cases/` | any authenticated user | Submit a case (JSON or multipart with repeated `attachments` parts). Throttled with `case_submit` |
| GET | `/cases/{id}/` | visible | Detail, including `attachments`, `latest_resolution` and `allowed_actions` |
| PATCH | `/cases/{id}/` | admin | Reclassify `category_id` and/or `priority` (with optional `note`) |
| POST | `/cases/{id}/transition/` | per lifecycle | `{to_status, reason?, resolution_note?}` |
| POST | `/cases/{id}/assign/` | admin | `{authority_id, internal_note?}`. Assigns or reassigns |
| GET | `/cases/{id}/assignment-recommendation/` | admin | `{authority, reason, rule_id}` |
| GET | `/cases/{id}/updates/` | visible | Paginated updates (internal ones removed for submitters) |
| POST | `/cases/{id}/updates/` | submitter, assigned authority, admin | `{body, kind, is_internal?, new_status?, resolution_note?, reason?, attachments?}` |
| POST | `/cases/{id}/verify-resolution/` | submitter | `{confirmed: bool, feedback}`. Feedback is required when `confirmed` is false |
| POST | `/cases/{id}/reopen/` | submitter (within window), admin | `{reason}` |
| POST | `/cases/{id}/deadline/` | admin | `{deadline_at (nullable), reason}` |
| GET | `/cases/{id}/timeline/` | visible | Merged history, filtered by visibility |
| GET / POST | `/cases/{id}/attachments/` | visible / participants | List, or upload `files` (multipart). Throttled with `attachment_upload` |
| GET | `/cases/{id}/attachments/{aid}/download/` | visible | Streams the file with `Cache-Control: private, no-store` |
| GET | `/cases/{id}/potential-duplicates/` | admin | `[{case, score, reasons}]` |
| GET / POST | `/cases/{id}/links/` | visible / admin | List or create links (`other_case_id`, `link_type`, `note`) |
| GET | `/categories/` | any | Active categories |
| GET | `/authorities/` | admin | Active authorities |
| GET | `/case-options/` | any | Enum labels, attachment limits, policy windows |
| POST | `/auth/token/` | public (throttled) | **Placeholder (Member B):** `{username, password}` → `{token, user}` |
| GET | `/auth/me/` | any | **Placeholder (Member B)** |
| POST | `/auth/logout/` | any | **Placeholder (Member B)** |

### Submission example

```http
POST /api/v1/cases/
Authorization: Token 9f…
Content-Type: application/json

{"title": "Projector not working in Hall A", "description": "The projector does not turn on.",
 "case_type": "complaint", "category_id": 1, "location": "Hall A",
 "requested_priority": "urgent", "declaration_accepted": true}
```

The response is `201` with the case detail, including `"case_number": "FMSC-2026-00001"` and `"status": "submitted"`.

These protected fields are rejected with `400` if they appear in a submission:

`status`, `assigned_authority(_id)`, `priority`, `case_number`, `deadline_at`, `solved_at`, `closed_at`, `verification_due_at`, `reopen_count`, `submitted_by`, `created_at`, `updated_at`.

The submitter's choice goes in `requested_priority`; only an administrator can change `priority`.

## Attachments

- **Allowed types:** jpg/jpeg, png, webp, mp4, mov, webm.
- **Content check:** the first bytes of each file must match its extension, so a renamed executable is rejected.
- **Size limits:** images up to `FMSC_MAX_IMAGE_MB` (default 5), videos up to `FMSC_MAX_VIDEO_MB` (default 50).
- **Count limit:** at most `FMSC_MAX_ATTACHMENTS_PER_CASE` (default 10) per case.
- **Storage:** files are saved under random names in `PRIVATE_MEDIA_ROOT`, which has no public URL. They are served only by the authorised download endpoint.

**Production note:** in production, also cap request size at the reverse proxy (for example `client_max_body_size 60m;` in nginx).
